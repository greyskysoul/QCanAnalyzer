## Features

- 🔌 **Multi-device support** — PCAN (PEAK USB/PCI), gs_usb (candleLight), ZCANFD/ZCAN (ZLG USBCANFD), SocketCAN (Linux), MockCAN (virtual)
- 🐧 **Cross-platform** — Windows + Linux, with native SocketCAN on Linux; unavailable adapters are hidden automatically
- 🪟 **Multi-session docking** — built on Qt Advanced Docking System: run multiple CAN sessions at once with tab groups and freely draggable layouts
- 📡 **CAN-FD support** — DLC 0–64, the data input accepts 64 bytes of hex; arbitration and data-phase baud rates are configured separately
- 📥 **Flexible transmission** — standard/extended/remote frames; periodic sending (period locked to prevent accidental edits); batched sending of a specified frame count; interruptible at any time
- 🔢 **Hex input** — data input filters out invalid characters, keeping only 0-9, A-F, and spaces
- 🔍 **Soft filters** — ID mask filtering plus per-channel enable checkboxes to focus on the traffic you care about
- 📊 **Channel identification** — the message table shows a channel column so multi-channel devices can distinguish sources
- 💾 **CSV export** — save all TX/RX frames (including channel info) to CSV in one click
- 🔗 **Disconnect detection** — connection is monitored every 500 ms; gs_usb supports automatic channel recovery; ZCANFD guards against double-open
- 🌍 **Multilingual** — built-in Simplified Chinese / English translation system
- 🎨 **High-DPI aware** — renders correctly at 175% scaling
- 🧪 **MockCAN virtual adapter** — automatically available in Debug builds for testing and demos without hardware

| **MockCAN**   | Cross-platform  | Virtual adapter, Debug builds only, for hardware-free testing |

### SocketCAN Notes on Linux

SocketCAN **does not support setting the baud rate in software**; configure it with `ip` before connecting:

```bash
sudo ip link set can0 type can bitrate 500000
sudo ip link set up can0
# Virtual CAN for testing:
sudo modprobe vcan
sudo ip link add dev vcan0 type vcan
sudo ip link set up vcan0
```

## Quick Start

1. Download the package for your platform from [Download](#download) or [Releases](https://github.com/greyskysoul/QCanAnalyzer/releases/latest) and extract it
2. Run `QCanAnalyzer` (Linux) or `QCanAnalyzer.exe` (Windows)
3. On the welcome page click **New Session**, choose device / channel / baud rate, and start sending and receiving
4. Without hardware, use the **MockCAN** virtual adapter in Debug builds

## Building

See [BUILD.md](BUILD.md) for detailed steps; the short version:

### Requirements

- **Qt 5.15+** (MinGW 64-bit / GCC recommended)
- **Windows** or **Linux**
- Git + Git LFS

### Steps

```bash
# 1. Clone the dependency libraries (libs/ is not tracked, you must prepare it manually)
mkdir -p libs && cd libs
git clone --depth 1 --branch 4.5.0 https://github.com/githubuser0xFFFF/Qt-Advanced-Docking-System.git
git clone --depth 1 https://github.com/Simsys/qhexedit2.git
# China mirror: git clone https://gitee.com/czyt1988/Qt-Advanced-Docking-System.git
cd ..
```

```bash
# 2. Pull LFS assets and add the missing ADS version header (required for qmake builds)
git lfs pull
cp ci/ads_version.h libs/Qt-Advanced-Docking-System/src/ads_version.h
```

**All device DLLs / .a files are stored in `third_party/` via Git LFS**; after cloning, make sure LFS files are pulled:

```bash
git lfs pull
```

**Windows — PCAN devices**:

```bash
# PCANBasic.dll is stored in third_party/pcan/ via Git LFS
# You still need the PEAK driver: https://www.peak-system.com
```

**Windows — gs_usb devices**:

```bash
# gs_usb (candleLight) uses the candle API linked statically, no external DLL needed
# Install the WinUSB driver (e.g. with Zadig: https://zadig.akeo.ie/)
```

**Windows — ZCANFD / ZCAN devices**:

```bash
# ControlCANFD.dll / ControlCAN.dll are stored in third_party/zcanfd/ and third_party/zcan/ via Git LFS
# Install the ZLG USBCAN driver (ships with the device)
```

**Linux — ZCANFD devices**:

```bash
# libcontrolcanfd.a is stored in third_party/zcanfd/ via Git LFS
# Statically linked, no extra runtime dependencies
```

**Linux**:

```bash
# On Linux, gs_usb and SocketCAN both go through kernel drivers, no extra DLLs needed
# Make sure the kernel modules are loaded:
sudo modprobe gs_usb        # candleLight devices
sudo modprobe can; sudo modprobe can_raw  # SocketCAN
```

```bash
# 3. Build (see BUILD.md for details)
mkdir -p build && cd build
qmake "CONFIG+=release" ../QCanAnalyzer.pro
make -j$(nproc)   # Linux
mingw32-make -j   # Windows MinGW
```

> You can also use the repository's GitHub Actions workflow to build in the cloud (see [.github/workflows/build.yml](.github/workflows/build.yml)).

## Adding Another CAN Device

Subclass `CanInterface` and implement the pure virtual functions to add a new device:

```cpp
class MyAdapter : public CanInterface {
    Q_OBJECT
public:
    QList<CanDeviceInfo> scanDevices() override;
    bool open(int channel, CanBaudRate baud,
              CanDataBaudRate dataBaud = CanDataBaudRate::None) override;
    void close() override;
    bool isOpen() const override;
    bool sendMessage(const CanMessage &msg) override;
    QString adapterName() const override { return "MyDevice"; }
};
```

Then register the adapter in `CanSessionWidget`. A complete integration touches **6 places** (new adapter files, the `CanAdapterType` enum, the `.pro` source list, the `SessionConfigDialog` combo box and scan branch, the `CanSessionWidget` member and `connectDevice()` branch, and the `CanManager` tab title branch); see [AGENTS.md](AGENTS.md) for the checklist.
